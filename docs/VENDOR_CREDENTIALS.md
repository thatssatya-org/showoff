# Portfolio vendor credentials and operator configuration

**Status:** implementation input checklist

Do not send any secret, refresh token, private key, password, recovery code, or API token through chat, commit it to Git, place it in frontend code, or copy it into an LLM prompt. Runtime credential values normally arrive through Docker secrets/environment configuration; the approved exception is the GitHub fine-grained PAT, which is entered through its Tailnet-restricted write-only management command and stored only as an encrypted MongoDB envelope.

## 1. Collect now — required for the complete target

| Integration | Gather from the owner | Spring environment variables | Notes |
| --- | --- | --- | --- |
| GitHub | GitHub username and a fine-grained PAT restricted to the read-only contribution/profile/repository data required by the approved GitHub projection | `PORTFOLIO_GITHUB_USERNAME`; submit the PAT once through the Tailnet-restricted `POST /internal/v1/provider-profiles/github/pat` command with a body containing only `token` | The API uses `samsepiol-library` `token-management` to encrypt and persist the PAT as an opaque Mongo envelope. No GET/export endpoint exists. A token is optional for basic public REST reads but required for dependable GraphQL contribution data and higher limits. Do not grant write, administration, Actions, packages, or organisation-management permissions. |
| Spotify | Spotify Developer app client ID, client secret, registered redirect URI, and an owner-authorised refresh token generated by the backend OAuth flow | `PORTFOLIO_SPOTIFY_CLIENT_ID`, `PORTFOLIO_SPOTIFY_CLIENT_SECRET`, `PORTFOLIO_SPOTIFY_REDIRECT_URI`, `PORTFOLIO_SPOTIFY_REFRESH_TOKEN` | The app must be set up under the account that owns the music data. Gather scopes only after endpoint verification; default to the minimum required for approved On Repeat/recent/top snapshots. |
| Instagram / Meta | Meta app ID, app secret, Graph API version, Professional Instagram account ID, linked Facebook Page ID, long-lived access token, and confirmation that required permissions/app review are granted | `PORTFOLIO_META_APP_ID`, `PORTFOLIO_META_APP_SECRET`, `PORTFOLIO_META_GRAPH_API_VERSION`, `PORTFOLIO_INSTAGRAM_ACCOUNT_ID`, `PORTFOLIO_META_PAGE_ID`, `PORTFOLIO_META_ACCESS_TOKEN` | A personal Instagram account cannot provide the required official feed integration. No scraping fallback. |
| YouTube | Google Cloud project ID, YouTube Data API v3 API key for public reads, channel ID; OAuth client ID/secret/redirect URI/refresh token only if owner-only/private selection is explicitly enabled | `PORTFOLIO_YOUTUBE_API_KEY`, `PORTFOLIO_YOUTUBE_CHANNEL_ID`, optional `PORTFOLIO_YOUTUBE_CLIENT_ID`, `PORTFOLIO_YOUTUBE_CLIENT_SECRET`, `PORTFOLIO_YOUTUBE_REDIRECT_URI`, `PORTFOLIO_YOUTUBE_REFRESH_TOKEN` | API key restrictions: YouTube Data API only, known server egress IPs when stable, quotas monitored. Channel RSS is a no-credential public fallback for uploads. |
| LinkedIn | LinkedIn Developer application client ID, client secret, registered redirect URI, approved products/scopes, and member authorization/refresh token only after LinkedIn grants the relevant access | `PORTFOLIO_LINKEDIN_CLIENT_ID`, `PORTFOLIO_LINKEDIN_CLIENT_SECRET`, `PORTFOLIO_LINKEDIN_REDIRECT_URI`, optional `PORTFOLIO_LINKEDIN_REFRESH_TOKEN` | Do not expect general profile/job/post read access. The manual profile/pinned-post fallback requires only public URLs, not a token. |
| Newsletter delivery | SMTP provider hostname, port, TLS mode, username/API key/password, approved sender address/display name, reply-to address, and mail domain DNS control for SPF/DKIM/DMARC | `PORTFOLIO_SMTP_HOST`, `PORTFOLIO_SMTP_PORT`, `PORTFOLIO_SMTP_USERNAME`, `PORTFOLIO_SMTP_PASSWORD`, `PORTFOLIO_SMTP_FROM_ADDRESS`, `PORTFOLIO_SMTP_FROM_NAME`, `PORTFOLIO_SMTP_REPLY_TO` | Listmonk needs SMTP to issue double-opt-in and unsubscribe mail. Do not run an open home SMTP relay. |
| Listmonk internal API | A dedicated Listmonk API username/password or token, internal base URL, and list ID/name | `PORTFOLIO_LISTMONK_BASE_URL`, `PORTFOLIO_LISTMONK_USERNAME`, `PORTFOLIO_LISTMONK_PASSWORD`, `PORTFOLIO_LISTMONK_LIST_ID` | Network-private only. This credential is backend-to-Listmonk; it is never exposed to a browser. |
| MongoDB | Separate database username, random password, database name, and an optional explicit TLS CA path for production | `SPRING_DATA_MONGODB_URI` **or** `SPRING_DATA_MONGODB_HOST`, `SPRING_DATA_MONGODB_PORT`, `SPRING_DATA_MONGODB_DATABASE`, `SPRING_DATA_MONGODB_USERNAME`, `SPRING_DATA_MONGODB_PASSWORD` | Use a least-privilege database user. The local Compose defaults must be replaced before deployment. |
| Application cryptography | Random 32-byte base64 encryption root key, key ID, a separate random cookie/state signing key, and a collector signing secret | `PORTFOLIO_CRYPTO_CURRENT_KEY_ID`, `PORTFOLIO_CRYPTO_CURRENT_KEY_BASE64`, `PORTFOLIO_OAUTH_STATE_SIGNING_KEY`, `PORTFOLIO_COLLECTOR_HMAC_KEY_BASE64` | Generate with a CSPRNG. Rotate keys through an explicit versioned process. Never reuse Mongo or vendor secrets. |
| Homelab collector | Collector ID plus the matching per-collector signing secret; optional mTLS client certificate/key if enabled | `PORTFOLIO_COLLECTOR_ID`, `PORTFOLIO_COLLECTOR_HMAC_KEY_BASE64`, optional `PORTFOLIO_COLLECTOR_MTLS_*` | The collector posts allow-listed aggregates only over Tailnet/private routing. It never receives public admin credentials. |

## 2. Public configuration — gather, but not secret

These values are content/operator configuration. They belong in an owner-managed content document or local configuration, never hard-coded into a component.

- Canonical domain, public API origin, final OAuth redirect origins, and a contact address.
- GitHub username, Spotify/Instagram/LinkedIn/YouTube canonical profile URLs and YouTube channel ID.
- Approved social/link-hub URLs, avatar, bio, project metadata, homelab-safe data policy, privacy policy, and newsletter consent copy/version.
- Provider capability enablement: e.g. `GITHUB_ACTIVITY`, `SPOTIFY_ON_REPEAT`, `YOUTUBE_UPLOADS`. Absence is expected and returns `204 No Content` on the individual generic capability route.
- Exact sender DNS records from the SMTP provider: SPF, DKIM selector/public key, and DMARC policy. DNS write credentials are not needed by the application unless automated DNS provisioning is explicitly selected.

## 3. Infrastructure credentials — conditionally required

| Situation | Required material | Environment-variable policy |
| --- | --- | --- |
| Self-hosted Temporal | No application secret for the local default namespace; secure the service network. If namespace authentication is enabled, use a dedicated API key/certificate. | `PORTFOLIO_TEMPORAL_TARGET`, `PORTFOLIO_TEMPORAL_NAMESPACE`, optional `PORTFOLIO_TEMPORAL_API_KEY` / mTLS variables. |
| Tailscale deployment/collector onboarding | Ephemeral, tagged, pre-authorised auth key only when automation must join a node. | `TS_AUTHKEY` belongs to the deployment/collector environment only, never the public API container. Revoke after provisioning. |
| Reverse proxy / DNS automation | Cloudflare/registrar API token limited to the specific zone and required DNS scope, only if automation is chosen. | Keep in deployment tooling, not Spring API runtime. Prefer manual DNS when low-frequency. |
| GitHub Actions image publishing | Fine-grained GitHub token or scoped registry token with package write only. | CI secret only. The deployed application must not possess it. |
| Error reporting / uptime monitoring | Separate project DSN or API token if explicitly chosen. | Optional. Keep operational telemetry private and PII-free. |

## 4. Explicitly not required

- No visitor credential, no frontend OAuth client secret, and no database password in a browser build.
- No Instagram/LinkedIn scraping token, cookie export, headless browser session, or third-party feed widget key.
- No Spotify playback control scope, no GitHub write scope, no Meta account-management scope, and no Google account password.
- No homelab device SSH password, Docker socket credential, Tailscale node key, Grafana credential, or private service URL.
- No global personal access token shared between vendor adapters.

## 5. Secure hand-off checklist

- [ ] Create a separate developer app/service account per provider where the vendor permits it.
- [ ] Set exact HTTPS redirect URIs; do not use wildcard callbacks.
- [ ] Record the token owner, scopes, creation date, expiry/rotation date, and revocation procedure in the private operator runbook.
- [ ] Limit API keys by API, IP/egress path, referrer only where applicable, and quota.
- [ ] Place values in untracked local environment files or Docker secrets. Confirm `git check-ignore .env` succeeds.
- [ ] Verify source, build artifacts, browser network traffic, logs, traces, and OpenAPI examples contain only variable names or redacted values.
- [ ] Start with GitHub, MongoDB, cryptographic keys, and SMTP/Listmonk. Add social-provider credentials only when their official app approval is complete.
- [ ] Rotate any credential accidentally copied to chat, shell history, a commit, an issue, a screenshot, or an LLM prompt.
